# Vedika Ayurveda — Next.js E-commerce (COMPLETED MVP)

## What was built
A complete single Next.js 14 (App Router) app at `D:\biotic\design-ayurveda` — "Vedika Ayurveda", an INR/India Ayurveda store. Built to replace the HTML mockups in `mockups/` (index/shop/category/product/about/blog/contact + css/js) with a real, deployable app. Derived from the `sesto-dev/next-prisma-tailwind-ecommerce` template but fully re-written to this stack.

## Stack (as agreed with user)
- Next.js 14 App Router + TypeScript, Tailwind (design tokens ported from mockups: bg #F7F1DE, green #2F4A3C, gold #C68A2E, red #A6402F, vata #6C6094, etc.; Fraunces + Work Sans fonts via next/font).
- **Prisma + SQLite (DEV) / Postgres via Neon (PROD).** User chose: dev uses local SQLite, production uses Neon DB.
  - `prisma/schema.prisma` is the canonical schema with `provider = "sqlite"` and is **SQLite-compatible**: NO enums (Role/OrderStatus are `String` fields with "ADMIN"/"CUSTOMER" and "PENDING" etc.), list columns (`images`, `ingredients`, `keywords`, `dosha`) are `String` (comma/newline-delimited, NOT `String[]` — SQLite has no arrays/Json support in Prisma 5). `Order.number` is a `String` (no `autoincrement()` on non-PK in SQLite) generated in `src/app/api/checkout/route.ts` as `VD<8digits>`.
  - `prisma/schema.postgres.prisma` is GENERATED by `scripts/make-prod-schema.mjs` (swaps provider to "postgresql") — do NOT edit by hand.
  - Scripts: `db:push` (sqlite dev), `db:setup:prod` (gen postgres schema + generate + db push + seed), `vercel-build` (postgres generate + db push + next build).
- Auth: **NextAuth v4 credentials** (bcrypt), JWT session with `role` (string union `src/types/roles.ts`, NOT a Prisma enum). `src/middleware.ts` protects `/account/*` and `/admin/*`.
- State: **Zustand** (`src/store/useCart.ts`, `useWishlist.ts`, persisted localStorage) + **React Query** (admin) + SessionProvider.
- Payments: **PayU India** hosted checkout (`src/lib/payu.ts`). Flow: `/checkout` -> POST `/api/checkout` (creates PENDING order w/ generated number) -> auto-POST to PayU -> `/api/payu/callback` verifies & marks PAID -> `/checkout/success|failure`.
- `src/lib/utils.ts` exports `asStringArray(v)` to normalize the delimited list columns back to `string[]` in the UI (used in ProductCard, product page, BuyBox, WishlistButton, data.ts filter).

## Key files
- `src/app/layout.tsx` store chrome (SiteHeader/SiteFooter, cart drawer). `src/app/admin/layout.tsx` separate admin shell.
- Storefront pages: `/`, `/shop` (server filter by category/dosha/tag/search via searchParams), `/category/[slug]`, `/product/[slug]`, `/categories`, `/about`, `/blog`, `/blog/[slug]`, `/contact`, `/search`, `/wishlist`, `/login`, `/register`, `/account` (dashboard), `/account/orders`, `/checkout` (+ success/failure).
- Admin: `/admin` dashboard, `/admin/products` (modal CRUD form), `/admin/categories`, `/admin/posts`, `/admin/orders` (status dropdown), `/admin/customers` — all via `/api/admin/*` (admin-guarded).
- `src/lib/data.ts` server data fetchers; `src/components/store/ProductImage.tsx` SVG placeholder fallback (no real product images exist yet — schema uses `imageUrl`/images[]; seed points to `/images/products/*.jpg` which don't exist, so placeholders show).
- `prisma/seed.ts` seeds 12 products, 4 categories, 6 blog posts, admin (admin@vedika.in / admin1234) + customer (customer@vedika.in / customer123).
